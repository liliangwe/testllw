# Todo CLI 设计文档

## 1. 概述

- **项目名称**：Todo CLI
- **目标**：帮助内部用户通过命令行记录日常待办事项
- **目标用户**：内部开发者
- **最小闭环**：纯创建（新增待办事项），不包含查看、编辑、删除功能

## 2. 技术选型

| 维度 | 选择 | 理由 |
|------|------|------|
| 语言 | Python 3.9+ | 开发快速，零编译，内部友好 |
| 依赖 | 仅标准库 | `argparse` + `json` + `pathlib`，零第三方依赖 |
| 存储格式 | JSON 文件 | 人类可读，结构清晰 |
| 数据路径 | `~/.todo/tasks.json` | 用户主目录下，不污染工作区 |
| 命令入口 | `todo` | 简短易记，通过 `pyproject.toml` 注册 |

## 3. 命令接口

### 3.1 唯一支持的命令

```
todo add -n <事项名称> -d <事项描述>
```

| 参数 | 简写 | 必填 | 说明 |
|------|------|------|------|
| `--name` | `-n` | 是 | 事项名称，不能为空 |
| `--description` | `-d` | 否 | 事项描述，默认为空字符串 |

### 3.2 使用示例

```bash
$ todo add -n "写周报" -d "周五前完成本周工作总结"
✅ 已添加待办: 写周报

$ todo add -n "买菜"
✅ 已添加待办: 买菜
```

### 3.3 错误处理

- 缺少 `-n` 参数时，输出错误提示并退出（退出码 1）
- 名称包含非法字符（如换行符）时拒绝并提示
- 文件系统不可写时，输出具体错误并退出

## 4. 数据模型

### 4.1 JSON 结构

```json
[
  {
    "name": "事项名称",
    "description": "事项描述",
    "created_at": "2026-10-15T12:00:00"
  }
]
```

### 4.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 事项名称，非空 |
| `description` | string | 否 | 事项描述，默认为 `""` |
| `created_at` | string | 自动 | ISO 8601 格式时间戳，创建时自动生成 |

### 4.3 存储行为

- 数据文件路径：`~/.todo/tasks.json`
- 如目录 `~/.todo/` 不存在，自动创建
- 如文件不存在，初始化为空数组 `[]` 后追加
- 每次 `add` 操作读取 → 追加 → 写回（保证数据不丢失）
- 使用原子写入：先写临时文件再 rename，防止写入中断导致数据损坏

```bash

```

安装后即可在终端直接使用 `todo` 命令。

## 7. 验收标准

| 编号 | 场景 | 预期结果 |
|------|------|----------|
| AC-1 | `todo add -n "测试" -d "描述"` | 写入 `~/.todo/tasks.json`，输出 ✅ 确认 |
| AC-2 | `todo add -n "无描述"` | 写入成功，description 为空字符串 |
| AC-3 | `todo add`（缺 -n） | 退出码 1，输出错误提示 |
| AC-4 | 首次运行（无 ~/.todo 目录） | 自动创建目录和文件 |
| AC-5 | 连续多次 add | 全部追加到数组末尾，不会覆盖历史 |
